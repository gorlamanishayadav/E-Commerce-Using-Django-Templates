### 1. PROJECT TITLE
**MyStore – Full-Stack E-Commerce & Inventory Management Web Application**
*(E-Commerce Platform Using Django Templates, Django ORM, and MySQL/SQLite)*

---

### 2. PROBLEM STATEMENT
Traditional retail systems and legacy e-commerce platforms often encounter critical operational bottlenecks, including:
- **Cart-to-Checkout Inconsistencies & Race Conditions**: Inability to manage simultaneous purchases leading to negative stock, overselling, and inventory discrepancies.
- **Cart Abandonment & Friction**: Clunky multi-step navigation, lack of persistent shopping carts per authenticated user, and rigid shipping address management.
- **Lack of Unified Inventory & Order Control**: Store managers lack an integrated dashboard to monitor low-stock thresholds, adjust live stock counts, and supervise real-time order lifecycle state transitions (Pending -> Confirmed -> Shipped -> Delivered -> Cancelled).
- **High Licensing Costs & Monolithic Bloat**: Small to mid-sized businesses require an affordable, modular, secure, and easily extensible web platform built with industry-standard frameworks.

---

### 3. PROJECT OBJECTIVE
The primary objective of this project is to design, develop, and deploy an end-to-end, secure, and robust full-stack e-commerce web platform.
Key objectives include:
1. **Seamless Customer Experience**: Enable users to securely register, login, browse categorized product catalogs, search dynamically, manage shopping carts, maintain multiple delivery addresses, and track order histories.
2. **Atomic Order Processing**: Implement transaction-safe checkout workflows ensuring data integrity, stock deduction, and automated stock restoration upon order cancellations.
3. **Comprehensive Admin & Inventory Management**: Provide staff/admin users with a dedicated control panel to oversee business analytics (total revenue from delivered orders, orders count, product counts, user metrics), live inventory monitoring (In-Stock, Low-Stock, Out-of-Stock alerts), and manual stock adjustments.
4. **Clean & Scalable Architecture**: Adhere to Django's Model-Template-View (MTV) pattern with modular applications (`users`, `products`, `cart`, `orders`), secure session handling, and optimized database queries.

---

### 7. DATABASE STRUCTURE & ENTITY RELATIONSHIPS

#### Database Models & Relational Schema:
1. **User (Django Built-in `auth_user`)**:
   - `id` (PK), `username`, `email`, `password`, `is_staff`, `date_joined`
   - Relations: `1:1` with `Cart`, `1:N` with `Address`, `1:N` with `Order`

2. **Address (`users.Address`)**:
   - `id` (PK)
   - `user` (FK -> `User`, `on_delete=models.CASCADE`)
   - `full_name` (CharField), `phone` (CharField), `address_line` (TextField), `city` (CharField), `state` (CharField), `pincode` (CharField), `created_at` (DateTimeField)

3. **Category (`products.Category`)**:
   - `id` (PK), `name` (CharField), `description` (TextField)
   - Relations: `1:N` with `Product`

4. **Product (`products.Product`)**:
   - `id` (PK)
   - `category` (FK -> `Category`, `on_delete=models.CASCADE`, `related_name='products'`)
   - `name` (CharField), `description` (TextField), `price` (DecimalField: max_digits=10, decimal_places=2), `stock` (PositiveIntegerField: default=0), `image` (ImageField -> upload_to='products/'), `created_at` (DateTimeField), `updated_at` (DateTimeField)

5. **Cart (`cart.Cart`)**:
   - `id` (PK)
   - `user` (OneToOneField -> `User`, `on_delete=models.CASCADE`)
   - `created_at` (DateTimeField)

6. **CartItem (`cart.CartItem`)**:
   - `id` (PK)
   - `cart` (FK -> `Cart`, `on_delete=models.CASCADE`, `related_name='items'`)
   - `product` (FK -> `Product`, `on_delete=models.CASCADE`)
   - `quantity` (PositiveIntegerField: default=1)

7. **Order (`orders.Order`)**:
   - `id` (PK)
   - `user` (FK -> `User`, `on_delete=models.CASCADE`)
   - `address` (FK -> `Address`, `on_delete=models.SET_NULL`, `null=True`)
   - `total_amount` (DecimalField: max_digits=10, decimal_places=2)
   - `status` (CharField: choices=['PENDING', 'CONFIRMED', 'SHIPPED', 'DELIVERED', 'CANCELLED'], default='PENDING')
   - `created_at` (DateTimeField)

8. **OrderItem (`orders.OrderItem`)**:
   - `id` (PK)
   - `order` (FK -> `Order`, `on_delete=models.CASCADE`, `related_name='items'`)
   - `product` (FK -> `Product`, `on_delete=models.SET_NULL`, `null=True`)
   - `quantity` (PositiveIntegerField), `price` (DecimalField)

### 8. IMPORTANT IMPLEMENTATION DETAILS

1. **Atomic Checkout Transactions (`transaction.atomic`)**:
   - The checkout pipeline wraps Order Creation, OrderItem Archival, Stock Deduction, and Cart Clearing inside a single `with transaction.atomic():` block.
   - If any step fails (e.g., database constraint or stock deficit), the entire transaction rolls back cleanly, preventing partial charges or corrupt cart states.

2. **Automated Stock Restoration on Order Cancellation**:
   - Customers can cancel orders in `PENDING` status. When cancelled, the view queries all associated `OrderItem` entries and increments the `product.stock` by each item's purchased quantity inside an atomic transaction.
   - If an admin shifts an active order status to `CANCELLED` from the administrative panel, the same inventory restoration safeguard executes.

3. **Query Optimization & N+1 Problem Prevention**:
   - Used `select_related('category')` in product catalog queries.
   - Used `select_related('product')` across cart items and order items.
   - Used `select_related('user', 'address')` in order history queries to avoid multiple round-trip SQL queries.

4. **Role-Based Access Control (RBAC)**:
   - Customer-restricted views are secured with `@login_required`.
   - Administrative dashboards (`admin_dashboard`, `admin_inventory`, `update_stock`, `admin_users`, `admin_order_list`, `admin_order_detail`) enforce `request.user.is_staff` permission verification, redirecting unauthorized users.

5. **Dynamic Search & Multi-Filter Query Engine**:
   - Implemented combined filtering in product views combining keyword matching (`name__icontains=search`) and foreign key filtering (`category_id=category_id`).

### 10. CHALLENGES FACED AND SOLUTIONS

1. **Challenge: Inventory Race Conditions & Negative Stock during Simultaneous Purchases**
   - *Problem*: If two users checkout the last available unit simultaneously, stock could drop below zero.
   - *Solution*: Implemented pre-checkout inventory validation checks coupled with `transaction.atomic()` to guarantee immediate validation and atomic stock deductions.

2. **Challenge: Stock Leakage upon Order Cancellation**
   - *Problem*: Cancelled orders leaving inventory counts depleted.
   - *Solution*: Engineered a dual-trigger rollback system (for customer self-cancellation and admin cancellation) that iterates over `OrderItem` records and returns exact quantities back to `Product.stock`.

3. **Challenge: Database Query Latency (N+1 Query Issue)**
   - *Problem*: Iterating over cart items and orders was generating dozens of individual SQL queries per page load.
   - *Solution*: Optimized views with `select_related()` for `ForeignKey` relationships, consolidating queries into single joined SQL queries.

4. **Challenge: Granular Administrative Authorization**
   - *Problem*: Preventing regular authenticated users from accessing inventory updates and order management.
   - *Solution*: Enforced server-side `is_staff` evaluation in views with instant user feedback via Django's `messages` framework and conditional template rendering.

5. **Challenge: Preserving Historical Order Pricing**
   - *Problem*: If a product's price changes in the catalog later, previous customer order receipts would reflect incorrect billing totals.
   - *Solution*: Stored a snapshot `price` field directly inside `OrderItem` at the exact time of order placement.

### 11. FINAL OUTPUT / DEMO WALKTHROUGH

#### Customer Journey Walkthrough:
1. **Landing & Discovery**: Customer lands on `home.html`, clicks "Products", searches for items or filters by category.
2. **Product Details & Carting**: Views product details, clicks "Add to Cart", views aggregated cart totals, and adjusts item quantities.
3. **Checkout & Address Selection**: Proceeds to checkout, selects an existing address from the address book (or adds a new address in their profile), and places the order.
4. **Order Confirmation & Tracking**: Customer is redirected to the order receipt page showing order ID, items list, prices, shipping address, and live status badge (`PENDING`).
5. **Cancellation (Optional)**: If needed, customer clicks "Cancel Order" while status is `PENDING`, instantly restoring stock.

#### Administrative Journey Walkthrough:
1. **Admin Login**: Staff user logs in and navigates to the **Admin Dashboard** (`/orders/admin/dashboard/`).
2. **Executive Overview**: Reviews real-time metrics: Total Users, Total Products, Total Orders, and Total Delivered Revenue.
3. **Inventory Management**: Navigates to **Inventory** (`/products/inventory/`), checks low-stock/out-of-stock badges, and updates stock directly via the inline numerical input.
4. **Order Fulfillment**: Accesses **Admin Orders** (`/orders/admin/`), opens order details, and advances the status from `PENDING` -> `CONFIRMED` -> `SHIPPED` -> `DELIVERED`.
